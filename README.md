# ミツカル（仮称）

エントリー前の就活生が「自分に合う業界・企業」を短時間で判断するためのWebアプリです。
価値観診断の結果と企業の情報（財務・過去の推移・社風や口コミ）を掛け合わせ、AIが根拠つきで解説します。

> 表示している企業とデータは、すべて架空のサンプルです。

```
.
├── dev.sh                  バックエンドとフロントエンドをまとめて起動
├── frontend/               React + TypeScript + Tailwind CSS + Recharts（Vite）
│   └── src/
│       ├── api.ts          サーバーとの通信と型
│       ├── ui.tsx          共通のUI部品
│       └── App.tsx         7つの画面と状態管理
└── backend/                Python（FastAPI）
    ├── app/
    │   ├── main.py         API の入口
    │   ├── catalog.py      企業データの読み込み（★EDINET に差し替える場所）
    │   ├── scoring.py      診断・相性スコア・条件の判定・業界平均との比較
    │   ├── store.py        保存（SQLite・匿名ID・自動削除）
    │   ├── schemas.py      データの形
    │   ├── data/           サンプルデータ（companies.json / meta.json）
    │   └── ai/             AI解説（Claude API とルールベース）
    ├── tests/              自動テスト（pytest）
    ├── requirements.txt
    └── .env.example        設定の見本
```

## 起動方法

```bash
./dev.sh          # → http://localhost:5173 を開く（Ctrl+C で両方止まる）
```

初回は Python の仮想環境（`backend/.venv`）と npm パッケージを自動で用意します。
スマホ実機で見る場合は `frontend` で `npm run dev -- --host` を使い、同じWi-Fiから表示されたアドレスを開きます。

### Claude API を使う場合

```bash
cp backend/.env.example backend/.env
# backend/.env の ANTHROPIC_API_KEY= にキーを入れて、./dev.sh を起動し直す
```

キーがなければ、データから自動作成した解説（ルールベース）で動きます。デモが止まることはありません。

### テスト

```bash
cd backend && .venv/bin/pip install -r requirements-dev.txt && .venv/bin/python -m pytest
```

## しくみ

### 相性スコア（`backend/app/scoring.py`）

| 要素 | 重み | 計算 |
|---|---|---|
| 価値観の近さ | 65% | 6軸ごとに、希望より会社が足りない分はそのまま、強すぎる分は半分だけ差し引く。高く付けた軸ほど重く数える |
| 条件の一致 | 25% | 重視する条件ごとに 一致=1／一部一致=0.5／不一致=0（希望年収・年間休日・地域と転勤・リモート・研修） |
| 志望業界 | 10% | 志望業界に含まれれば1（「まだ決まっていない」なら対象外） |

選んでいない要素は除いて、重みを配り直します。企業の知名度は使いません。カルテの「スコアの内訳」で、この計算をそのまま確認できます。
各指標の「良い水準か」は、同じ業界の平均（サンプル値）と比べて判定します。

### AI解説（`backend/app/ai/`）

1. 根拠の一覧をデータから決まった手順で作る（`evidence.py`）。AIに出典を作らせない
2. Claude（`claude-opus-5-5`）に、その根拠だけを使い、文ごとに根拠番号を付けるよう依頼する（`claude.py`、構造化出力）
3. 出力を検査する（`guard.py`）：根拠番号が実在するか／断定・決めつけの表現がないか／長すぎないか
4. 失敗したとき（キーなし・通信エラー・回答拒否・検査で不合格・1人あたりの回数上限）は、ルールベースの解説に自動で切り替える（`rules.py`）
5. 同じ企業と同じ診断結果の解説はキャッシュして再利用する（費用と待ち時間の削減）

安全上の理由で回答が断られたときは、API側で別モデルへ自動で切り替える server-side fallback（`fallbacks: "default"`）を有効にしています。
画面には、解説を作ったのが Claude かルールベースかを常に表示します。

### 保存と個人情報（`backend/app/store.py`）

- 保存するのは診断の回答と操作の状態だけ。名前やメールアドレスは受け取りません
- 利用者は匿名のランダムIDで識別します（Cookie：HttpOnly・SameSite=Lax）。DB にはIDのハッシュだけを保存します
- 最後に使ってから90日たったデータは自動で削除します。「入力したデータをすべて削除」で即時に完全削除します
- 状態を変えるリクエストには専用ヘッダーを必須にしています（他サイトからの送信を防ぐ補助）

### 無料プランと有料プラン

閲覧数（月5社・毎月1日にリセット）、比較の社数（2社／3社）、出来事・口コミの表示範囲は、すべてサーバー側で制御します。
無料プランには有料部分のデータそのものを送りません（画面でぼかすだけにしない）。設定画面の「（デモ）翌月にする」で、月替わりのリセットを確認できます。

## 本物のデータ・AIに差し替えるとき

| 差し替えるもの | 場所 | 今の中身 |
|---|---|---|
| 企業一覧・企業の詳細・業界平均 | `backend/app/catalog.py`（`companies()` / `get()` / `benchmark()`） | `app/data/*.json` のサンプル |
| AI解説 | `backend/.env` に `ANTHROPIC_API_KEY` を設定するだけ | キーがなければルールベース |
| 課金 | `PATCH /api/me` の `plan`（今はデモ用の切り替え） | 決済は未実装 |

画面側の `getCompanies()` / `getCompanyDetail(id)` / `getAiCommentary(companyId)` は、サーバーの API を呼ぶだけなので変更は不要です。

## 操作性（ボタン配置）の方針

| | スマホ（〜1023px） | PC（1024px〜） |
|---|---|---|
| メニュー | 画面下の固定ナビ | 左のサイドメニュー |
| よく使う操作 | 画面下部の固定バー（親指が届く範囲）<br>例：比較する／絞り込み／比較に追加／次の候補へ | 本文の右下に固定 |
| 絞り込み | 画面下から出るシート。決定ボタンは最下段 | 一覧の上に常時表示 |
| 企業カルテ | 縦1列（会社情報→AI解説→根拠→詳細） | 2列（左：詳細、右：AI解説と根拠を固定） |
| 診断 | 回答ボタンを画面下半分に配置 | キーボードの 1〜5 で回答、← で戻る |

- 画面上部には「戻る」「プラン表示」など使う頻度の低い操作だけを置いています
- タップ領域は高さ44px以上（専門用語の「?」も見た目より広く反応）
- 通知と用語説明は画面下に表示。一覧に戻るとスクロール位置を保持
- 削除の確認では「キャンセル」を最下段に置き、誤操作を防止
- 通信できないときは画面上部に案内と「再試行」ボタンを表示
